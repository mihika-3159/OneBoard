# Batch O/P evidence and closure checklist

Do not claim completion without passing evidence for the exact current revision.

- O: all eleven views in the mobile/tablet browser matrix; WCAG automated checks on all eleven tabs, accessible keyboard selection, named controls, contrast, visible data states, explicit session expiration and uncertain-write recovery; 250-row workflow inventory benchmark. Real human screen-reader validation remains separate from the browser accessibility tree; use NVDA with Firefox/Chrome and VoiceOver with Safari, traverse every view, dialogs and error announcement, and document results. Verify configuration and destructive actions only on disposable workspaces.
- P: complete hashed install, pinned Actions/model artifacts, SBOM, static and dynamic security, critical coverage, generated property and fuzz tests, restricted PostgreSQL HTTPS production browser journeys, concurrent real Ollama, randomized actual database restart cycles, soak tests, all three browser engines on Linux/Windows/macOS, bundle/latency/resource gates, and source-revision candidate receipt.
- The dynamic scan uses only synthetic accounts on the dedicated restricted-role loopback HTTPS service. It does not contact live integrations or scan external hosts. The consolidated report fails on missing, failed or incomplete sibling workflows and required artifacts.
- Automated evidence cannot establish independent screen-reader usability, external production hosting, real financial provenance, provider authorization, regulatory compliance, or signed independent attestations. Preserve the distinction in release notes.

For all new changes, inspect the CI run on the exact revision and record failures instead of removing or bypassing checks. The release-candidate receipt includes source head and build SHA, individual run IDs, artifact metadata, and a separate external NO_GO.
