# Batch G inference operations

For distributed dispatch, provision a private PostgreSQL database dedicated to the inference queue. Give only the API and inference workers access. Set INFERENCE_QUEUE_URL to its SQLAlchemy PostgreSQL URL in both services. Apply the application's normal database settings to the worker for tenant token accounting. Use verified TLS between hosts. Start one or more workers with `python -m scripts.inference_worker` before routing traffic to the API. Workers initialize the queue schema under a database lock. With no queue URL the gateway uses its synchronous local deployment mode.

The queue holds tenant prompts, partial output, and replies while the request is active. Fetch and deletion use both tenant and request ID. The worker clears the payload at completion. The caller removes the entry on exit and the worker removes expired entries. Disk and backup retention are deployment responsibilities. Two slots are shared across workers. A claim chooses the least recently served waiting tenant, then that tenant's oldest request. Claims are fenced by owner and lease. One expired claim can be recovered before the deadline if no partial output was published. Streamed work with published output expires on interruption to avoid replaying a different continuation. An abandoned caller cannot resume a request after its deadline.

Production workers sample their available host and cgroup memory and host load before generation. Set INFERENCE_MIN_FREE_MIB and INFERENCE_MAX_LOAD_PER_CPU to fit the inference host. With a remote provider these measurements describe the OneBoard worker. Dedicated local Ollama replicas can be configured with OLLAMA_LOCAL_REPLICA_PORT. Retries and failover share the request deadline. Each outbound attempt incurs a tenant token reservation. Only validated embeddings with a configured model digest qualify for the bounded per-process tenant cache, with a 60-second lifetime.

The founder command stream emits newline-delimited JSON. Text fragments are provisional. A final result carries model identity, simulation status and the output-limit flag. Closing the stream cancels local work and removes the durable queue request. A running worker polls ownership every half second and closes the provider connection on cancellation. Structured council, workflow and agent decisions consume completed, validated objects.

The dispatcher waits for an in-flight queue insertion before deleting a cancelled request. Workers flush the final buffered text before committing the terminal reply; a completed stream therefore delivers every fragment even when generation finishes inside the publish interval.
